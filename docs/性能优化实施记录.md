# 性能优化实施记录

日期：2026-09-23。实施分支：`codex/performance-cleanup`。原版基线：`58495e2a9522a12ff641c56762780add1663e099`。

本轮已完成作品预览加载、布局预计算、详情分包、渲染热路径与字体交付优化，并通过生产构建和浏览器验证。保留原来的 UI、作品排列、相机运动、字体家族、Shader 和艺术参数。代码在本地优化分支，尚未推送或发布 Worker；新版本字体已先行上传 R2，原字体继续保留。

原始问题与设计约束见 [性能优化与代码精简规划](./性能优化与代码精简规划.md)。规划中的数字是改造前快照，以下为实施结果和实际验证范围。

## 1. 已实施的变化

### 作品首屏与加载队列

- 删除等待全部 152 张封面完成后才创建场景的流程；先创建原场景和固定格子，按当前视野及邻域请求真实封面。
- 首页不再提前请求整库封面。临近探索区时预热；直接打开 `#work`、`#explore` 或通过中转页展开也可启动加载。同一个场景实例贯穿预览与全屏。
- 下载与解码最多并发 6 张，图片上传后才释放队列槽位，避免积压整库解码结果；同一 URL 去重。
- 每帧最多上传 2 张纹理，同时检查约 3 ms 的上传时间预算。单次上传本身不能被抢占，因此这不是每帧严格低于 3 ms 的保证。
- 超时 12 秒，自动退避重试最多 3 次；再次进入该卡片视野或恢复网络后可以重试。单张失败不改变格子，不阻塞其他卡片。
- 保留共享纹理。新增 128 MiB 封面纹理软预算，优先回收视野及预取邻域之外的旧纹理；可见内容可超出预算，避免为达标闪白。预算按 RGBA 与 mipmap 估算，不是实测显存。
- 首次就绪在真实可见封面完成绘制后通知；另记录当前可见封面完整就绪时间。下载完成不再等同于用户已经看见图片。

主要文件：`src/components/Portfolio.tsx`、`src/lib/portfolio/media.ts`、`tiles.ts`、`createScene.ts`。

### 拼图移到构建期

- 通过实际封面核验生成 `src/content/works/media.json`，记录真实宽高、文件大小与摘要。区分视频布局画幅和封面纹理画幅，保持原有 cover 裁切。
- 原求解算法完整迁至 `scripts/portfolio-layout.ts`、`scripts/portfolio-mosaic.ts`，种子与布局规则不变。浏览器删除旧求解入口。
- `scripts/build-portfolio.mjs` 从同一作品注册表生成 `gallery.generated.json`，自动检查作品 ID、矩形、分区面积和重叠。`npm run dev`、`npm run build` 自动生成，不需要联网下载素材。
- 正常浏览仅应用预计算坐标、原缩放和无限循环逻辑。新增作品时重新生成，无需维护另一份人工列表。

当前 168 件作品：60 张图片、86 条视频、16 首音频、3 个游戏、2 个项目、1 个网页；152 张实际封面合计 9,008,840 字节。布局版本：`60b880446a6926d5`。

### React 和代码分层

- 墙面读取摘要与布局；完整内容注册表和 `WorkDetail` 合并为按需加载边界，在悬浮或点击推进期间预取。没有为每件短记录拆成单独请求。
- `useWorkDetail` 统一缓存模块与 ID 索引，用请求序号阻止过期结果重新打开已关闭弹窗；加载失败后可重新尝试。
- 技能详情独立为 `SkillDetail.tsx`，按需加载；关联作品只读摘要。
- 游戏下载继续按真实进度保活，仅在显示的整数百分比变化时触发 React 状态更新，保留最初 0% 的显示。
- 未引入新的状态库、React Compiler 或全仓 memo 包装。连续运动仍在现有场景对象与 uniform 中更新。

### 渲染热路径

- 主场景完全白场后只清屏一次，resize 和逆向转场重置；仍保留原来的动画时间语义。
- 作品循环范围不变时复用单元分配结果；音频索引预先建立，静态图片不再逐帧写入无用的时间 uniform。
- hover 合并到每帧一次，点击仍即时检测。球面反向映射保留，用平面求交和空间分区替代全体 Mesh 拾取，圆角规则不变。
- 技能可见性改用 IntersectionObserver，减少每帧布局读取；取景矩阵和 DOM 状态只在相关值变化时更新。
- 星链边界复用节点和点数组，跳过相同的 clip-path / mask 写入，继续使用同一条原曲线。
- 保留粒子数、DPR、抗锯齿、反射、云雾、水面、柔光、噪声、转场时长和惯性参数。没有通过降低画质达成提速。

### 字体与 R2

- 字体子集改为从 TS / TSX 的字符串、模板与 JSX 文本提取字形，排除中文代码注释；字形来源、家族、字重和预加载顺序保持不变。
- 四个字体从 1,750,824 字节减至 1,674,876 字节，减少约 4.34%。新对象采用内容摘要文件名，缓存设置为 `public, max-age=31536000, immutable`。
- 已上传并校验新字体：`astra-kinghwa.d2af99208dcb.woff2`、`astra-zhuque.52a3bdf75aaa.woff2`、`astra-cinzel.6d29830a126c.woff2`、`astra-cormorant.9b3a19c612f2.woff2`。
- 未覆盖旧对象；代码回滚仍可使用旧字体。字体生成结果写入系统临时目录，仓库仅保留代码、样式和清单。
- 素材仍使用现有 R2 地址，增加连接预热。视频、音频继续点击后加载，游戏入口继续同源，Worker 的流式与 Range 转发保留。

## 2. 性能对照

同一台 Windows 机器、Chrome 153、1920 × 1080、DPR 1，使用前后两份生产构建，交替各跑 5 次，每次创建新的浏览器上下文。R2 素材由本机同一份缓存响应，以隔离公网抖动，比较代码、解码、布局与绘制等待。

这些结果不是公网冷缓存测试、慢网 SLA 或手机实机数据。计时为打开 `#work` 到可见封面就绪并等待两帧；原版必须等待全部封面，新版检查 `portfolio:visible-ready`。取景从中转预览连续展开，期间请求数包含预览视野及邻域。

| 指标 | 原版 | 优化版 | 说明 |
| --- | --- | --- | --- |
| 作品首屏可见时间中位数 | 2.265 秒 | 0.750 秒 | 减少约 67% |
| 5 次首屏时间范围 | 2.219–3.000 秒 | 0.750–0.796 秒 | 控制素材响应条件 |
| 首屏检查点前封面请求数中位数 | 152 | 46 | 减少约 70%；实际新值 45–46 |
| 每次最大主线程长任务 | 952–992 ms | 66–71 ms | 已消除约 1 秒的初始化阻塞，仍有超过 50 ms 的工作 |
| 初始 HTML 引用的外部 JS 原始字节 | 1,514,946 | 1,379,580 | 约减少 8.94% |
| 上述 JS 本机 gzip 估算字节 | 446,969 | 406,570 | 约减少 9.04%；不是线上传输实测 |

原布局算法独立运行约 1.4–1.56 秒，目前只在构建期执行。Three.js 仍是开场必需依赖，未宣称把整个 Three.js 从初始包移除。

5 次首屏时间原始值（秒，四舍五入到三位）：原版 `[3.000, 2.219, 2.235, 2.282, 2.265]`；优化版 `[0.766, 0.750, 0.750, 0.750, 0.796]`。

## 3. 视觉与交互验证

- **布局完全一致**：同一组真实尺寸输入，原算法输出与生成清单逐项 JSON 对照一致。
- **拾取一致**：桌面、移动端及不同相机位置共 12,000 次射线命中对照，结果无差异。
- **静态作品画面对照**：受控截图每通道平均绝对差约为 `[0.00000675, 0.00000675, 0.00000579]`，按 0–255 色值计算；只有极少量像素差异，并非数学意义的全零。
- 检查了探索页、技能卡片、水面、雾气、鼠标反馈、移动端 resize 和减少动态效果模式；未更改 Shader 源码与艺术参数。静态对照不等于对所有动画时刻逐帧证明。
- 首页未提前请求作品封面；直接哈希进入作品可渐进出现，图片、视频、音频和两个项目详情均可实际点击打开、关闭返回。
- 影音详情保持 `preload="none"`。实际 R2 视频和音频 Range 请求返回 206、正确 Content-Type 与 CORS；新字体缓存和分段响应也通过抽查。
- 涂鸦游戏实际进入和退出时，4 个宿主渲染器的绘制计数暂停，iframe 退出后移除。本轮未逐个完整游玩小车和 Ooqo，游戏内部未修改。
- 技能翻转中途反向滚动，进度由约 0.1166 回到 0.0620，最终回到 0；技能详情可按需加载。
- 注入可见封面 503，完成 3 次失败尝试期间其他卡片仍可点击；恢复网络后第 4 次请求成功，可见集合进入完整就绪状态。
- 镜头推进期间退出章节，异步详情不会迟到弹出；重新进入和点击正常。
- 1920 × 1080 切换到 390 × 844 正常；390 × 844 / DPR 2 / 触屏 / 减少动态效果模式显示 6 张静态技能卡片。

连续 20 轮正常动画进入退出，在第 5 / 10 / 20 轮采样：DOM 节点均为 1,435；四个上下文的活动纹理数分别保持为 4、5、121、25；JS 堆为 12,032,068、12,160,456、12,299,120 字节。纹理与 DOM 计数稳定，堆存在约 0.25 MiB 小幅漂移，不能据此声称内存完全恒定或所有泄漏都已排除。

`npm run typecheck`、`npm run build` 均通过；集成和故障恢复检查没有页面异常。基线已有的 render-target texture clone 与 ANGLE Shader 提示仍有观察到，未把它们算作新增页面错误，也未为消除提示改动有效特效。

## 4. 精简结果与本轮边界

已删除旧全量媒体等待路径、旧浏览器布局求解入口与内联重复详情职责，只保留一套现行加载逻辑。关键中文注释说明队列所有权、不可变布局、纹理重分配、视野保护和异步取消原因。新增脚本用于正式内容维护，不是留在主包中的诊断工具。

未发现可凭入口检查直接大批删除的主站模块，因此没有按文件名猜删 CSS、游戏入口或资源清单。保留无障碍、触屏、减少动态效果、错误恢复和许可证。

以下按实际条件保留或暂缓，并非已经达成的性能指标：

- 现有封面最大尺寸为 1440，按需加载与预算已显著减少首次成本。本轮未新增一套缩略图或重新压缩素材，避免改变清晰度与增加资源版本。
- 未进行纹理图集、KTX2 全库转码、WebGPU、单 renderer 重写、反射降频等高风险改造。
- 用户当前选择的是 R2 临时域名，未另选域名或改 DNS。公网冷加载仍可能受 `r2.dev` 限流、跨境链路和字体响应影响；本机对照结果不能替代这些网络条件。
- 没有给出未经测量的 GPU pass 时间、React Profiler 提交耗时、60 FPS 保证、10 Mbps / 2 Mbps 首屏承诺或 20 样本 p95。方案中的相关数字仍是后续线上设备测量目标。
- 固定媒体地址可能被覆盖，继续保留一小时缓存；只有新的不可变字体采用一年缓存。未清空 R2 回滚资源或重建游戏所需的 `_source`。

## 5. 维护与交付

新增 / 更换封面：上传 R2 → `npm run assets:inspect` → `node scripts/build-portfolio.mjs` → 检查内容和布局 → 提交代码及 JSON 清单。普通构建不下载素材。

新增中文文案：`python scripts/build-fonts.py` → 上传生成清单中的新字体并核验 → 提交清单和 CSS → 发布代码。旧字体保留以便回滚。

本地预览使用 `npm start`，地址 `http://127.0.0.1:3000/`，作品直达 `/#work`。Windows 上 Wrangler 预览可能锁定 `out/`；重新构建前先停止预览进程。

测量脚本、缓存、截图及原始 JSON 留在系统临时目录 `C:/Users/Admin/AppData/Local/Temp/resume-performance`，不进入仓库或生产包。主要证据为 `comparison.json`、`geometry-check.json`、`integration.json`、`edge-cases.json`、`range-cors.json` 和前后受控截图。临时目录可能被系统清理，本文件保留结论、方法和关键原始数字。

本轮没有推送 `main` 或执行 `wrangler deploy`，现有线上版本保持不变。后续发布优化分支时，R2 的新字体已经就绪。
